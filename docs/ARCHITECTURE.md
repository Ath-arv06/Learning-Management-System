# System Architecture Document
## Opt-Out University Learning Management System (LMS)

---

## 1. Architectural Principles

1. **Separation of Concerns (SoC)**: Strict decoupling between the presentation layer (React SPA), API gateway/business layer (Spring Boot), data persistence (MySQL 8.4), and cognitive AI services (Google Gemini).
2. **Defensive Security & Zero Trust on Frontend**: The frontend is treated as completely untrusted. All input validation, role checks, business logic, file inspections, and AI token handling reside strictly on the server.
3. **Stateless API & Cookie-Backed Session Security**: JWT tokens stored exclusively in `HttpOnly`, `Secure`, `SameSite=Strict` cookies to eliminate XSS token theft.
4. **Idempotence & Transactional Integrity**: Database operations are atomic and wrapped in ACID transactions with optimistic locking for concurrent grading and submissions.
5. **Human-in-the-Loop AI Governance**: AI serves as an advisory assistant. All automated scores and content generated by Gemini require human review and approval.

## 5. Security & Isolation Architecture

### 5.1 Role-Based Route and API Protection
- **Role Hierarchy**:
  - `ROLE_ADMIN` -> Can access Admin Portal and audit interfaces.
  - `ROLE_INSTRUCTOR` -> Can access Instructor Portal and assigned courses.
  - `ROLE_STUDENT` -> Can access Student Portal and enrolled courses only.
- **Method-Level Security**:
  Backend controllers enforce declarative authorization using `@PreAuthorize("hasRole('INSTRUCTOR') and @courseSecurity.isInstructorOfCourse(#courseId, authentication.principal)")`.
- **Tenant & Course Scoping**: Students cannot view quiz questions or answers before the scheduled exam window; submission endpoints verify that the submitting user matches the student enrollment.

### 5.2 Gemini AI Gateway Architecture
```
[Frontend Client]
       |
       | POST /api/v1/ai/course-query { courseId, question }
       v
[AiAssistantController]
       |
       +--> Verify Student Enrollment in Course (Security Boundary)
       +--> Retrieve Course Module Text / Transcripts from Database (Grounding Context)
       +--> Sanitize Prompt & Strip PII
       +--> Dispatch Server-to-Server Request to Google Gemini API
       |      Header: x-goog-api-key: ${GEMINI_API_KEY} (Kept Secret in Backend)
       v
[Google Gemini API]
       |
       v Responds with Grounded Explanation
[AiAssistantService]
       |
       +--> Audit Log AI Interaction (User ID, Course ID, Timestamp)
       +--> Return Clean JSON Payload to Client
```

## 6. Integration Points & External Interfaces
- **Email Gateway**: JavaMailSender with SMTP (configured for SendGrid/Amazon SES in production, Mailhog for local testing).
- **Object Storage**: Local file system abstraction implementing `StorageService` interface (pluggable with AWS S3 / MinIO for cloud deployments).
- **Meeting Bridge**: Dynamic generation of signed virtual room links (Google Meet / Zoom / Jitsi Meet).
